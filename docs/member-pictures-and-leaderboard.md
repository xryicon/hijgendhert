# Member presentation

Names in `/leden/[username]` are decoded once at the page boundary. The installed Vinext canonicalizes page parameters as URL-encoded strings; the decoded name must reach the client before it constructs an API query. Invalid escaping, slashes and repeated encoding fail closed. API input validation remains unchanged.

Discord pictures use the existing `identify` and `guilds.members.read` response. A server-specific image takes precedence over the global image. No extra OAuth scope or Discord request is added. Missing or failed images retain the clan artwork or account-type icon.

The session endpoint saves only a display directory in `clan:7059:avatars`: Discord id, normalized display names, public picture URL and refresh time. This is never an ownership claim or access-control source. It is not part of a private game-account snapshot or audit log. Selecting a RuneScape account cannot attach a picture to that public profile. A picture is matched only when both directions are unambiguous against the current WOM roster. Duplicate names, departed players and identities not refreshed for 30 days have no public association. `/api/clan/avatars` returns only WOM player ids and whitelisted CDN URLs. Existing members need to visit while signed in before their picture can be discovered.

The event leaderboard is separate from clan rank and event adjustments. It covers finished classic and team Hijgend Hert competitions returned by WOM's unpaginated group catalogue. Only positive progress in the scored metric counts as participation. A multi-metric event uses the `total` metric. Scores are ordered before filtering the current clan roster, so departed members do not change historical finishing places. Equal scores share historical competition places (1, 1, 3). Team components use the team's total positive gains; members without positive progress do not qualify.

An event/week counts once, as explicitly requested by the clan owner. Group components by their Amsterdam start/end dates and family (skills, bosses, team events, EHP or EHB). Within a round, repeated metric sets are duplicate trackers; retain the lowest WOM id deterministically. This removes the duplicated Construction competition and combines multi-boss weeks, including small differences in start/end times. Team and individual rounds remain separate. A round contributes only after all its canonical components have final summaries. The member's component places are averaged within the round, then each participated round has equal weight in the overall mean. This is the site's WOM-based performance score, not an external bingo-board result.

At least five completed event weeks are required for a leaderboard position, as selected by the clan owner. Qualified members sort first: lower means, then more events, then stable player id. Assign unique consecutive leaderboard positions (1, 2, 3, 4) after sorting; never round averages into positions. The fractional mean remains internal, replacing the confusing second position-like column. Members below the minimum remain visible after qualified members, with their participation count and the number of events still needed. The API returns `minimumEvents` so the displayed rule matches the ranking calculation. Search and account-type filters change visibility without recalculating clan positions.

Final per-component summaries persist in `clan:7059:event-leaderboard`. Four missing or revised components are collected per shared batch, using the existing WOM cache and rate limits. A stored lease prevents simultaneous browsers from multiplying that work. The UI reports processed/total rounds, with the underlying tracker count in an explanation; it withholds leaderboard positions until the full result set is available. Ongoing, foreign and pre-finish snapshots cannot become final results. Revised event metadata invalidates the corresponding summary. Existing classic summaries are reused when grouping changes. No personal Discord data is included in the leaderboard.

References: [Discord CDN formats](https://docs.discord.com/developers/reference#image-formatting), [WOM group catalogue implementation](https://github.com/wise-old-man/wise-old-man/blob/master/server/src/api/modules/competitions/services/FindGroupCompetitionsService.ts).

Validation: `tests/member-presentation.test.mjs` covers name decoding, image matching and ranking math. `tests/member-account.worker.test.mjs` exercises public profiles with spaces, directory persistence and current-roster filtering, plus leaderboard persistence without refetching finalized results.
